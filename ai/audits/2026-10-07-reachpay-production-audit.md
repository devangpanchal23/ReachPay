## Findings and remaining risks

- No live Paytm or PhonePe transaction, refund, terminal-health request, or settlement reconciliation was performed. Unit tests use intercepted HTTP to verify request construction and failure handling, not as evidence that a provider accepted a payment.
- Paytm’s official public Payment Request API documents `clientId`, `reqHash`, `txnDate`, `merchantTxnId`, integer-paise `txnAmount`, optional `txnNumber`, and `mid`. Paytm must confirm the merchant-specific checksum/client ID contract and ECR void eligibility before production enablement. The API’s payment request acceptance is not a completed card payment; terminal status remains authoritative. [Paytm Payment Request API](https://www.paytmpayments.com/docs/api/pos-payment-request-api/), [Paytm POS status API](https://www.paytmpayments.com/docs/api/pos-payment-request-status-api?ref=poscpayapidetails), [Paytm POS void/cancel API](https://www.paytmpayments.com/docs/api/pos-void-and-cancel-api?ref=poscpayapidetails).
- PhonePe’s public Offline Partner material is an onboarding/partner program for POS/ERP integration, not a public executable EDC API contract. This implementation remains blocked pending PhonePe partner approval and the private technical package/device access. [PhonePe Offline Partner Program](https://www.phonepe.com/business-solutions/offline-merchant/partner-program/), [PhonePe partner registration](https://www.phonepe.com/business-solutions/offline-merchant/partner-program/register/).
- PostgreSQL migrations, least-privilege role behavior, SQL concurrency under real PostgreSQL, backup/restore, and database-backed end-to-end flows remain unverified because the configured database refused connections.
- No TypeScript checker is configured. `npm audit` cannot resolve a dependency tree without the project lockfile. Neither result should be treated as a clean security scan.
- The UI audit covered route and POS workspace smoke checks, mobile widths, validation, and browser console at the available local run; it was not a full authenticated test of every product workflow because the local database/provider dependencies are unavailable.
